# Making Relic Drift

This project is a practical test of making a small playable game with **all visible 3D assets generated by Idol Studio**. It was created in a new folder and repository; the existing Idol Studio repository was used read-only.

## Tool chain

| Tool | Job |
| --- | --- |
| Built-in OpenAI `image_gen.imagegen` tool | Create three new 2D source images with transparent alpha |
| [Idol Studio C#](https://github.com/shohdi/idol-csharp), commit `1ff3ee61a2f719637cfb6ac8113b2ec9494fa082` | Convert those PNGs into original Gaussian splats |
| [Speridlabs Idol](https://huggingface.co/speridlabs/idol), revision `2731c2291fc65a797c5cb627a5e5526fc1490902` | The unchanged image-to-3D model used by Idol Studio |
| TorchSharp 0.107.0 / LibTorch 2.10.0 CUDA 12.8 | Native backend for the C# asset-generation process |
| Unity 6000.2.6f1, Built-in Render Pipeline, Direct3D 11 | Assemble, render, animate, test and build the game |
| C# | Gameplay, interface, collision checks, audio synthesis, splat rendering, audit and build scripts |

The game itself uses only Unity and the included generated assets. It does not run the model while playing.

## Rules followed

- Every visible world prop is an instance of one of the three Idol-generated assets.
- No downloaded FBX, OBJ, GLB, glTF, Blend, or other third-party 3D asset was used.
- No asset was modeled by hand, built with Unity primitives, or created with Blender.
- The original generated Gaussian positions, colors, scales, rotations and opacities are retained. Unity applies its coordinate reflection on import.
- Object placement, uniform scaling, hover, bank and spin are rigid transform animation, not geometry editing.
- Collision is a lane/distance decision in code. There are no replacement meshes hidden behind the splats.
- The star backdrop and HUD are two-dimensional UI graphics. The Gaussian shader's procedural screen quads are rendering support for Idol's output, not authored 3D models.
- No music or sound asset was downloaded. `RelicAudio.cs` synthesizes a 16-second ambient loop plus pickup, impact, launch, UI and finish cues from oscillators/noise.
- No bones were needed for this flying-prop game.

## Step 1: generate the source images

The built-in image-generation tool was called once per asset with `transparent_background: true`. Outputs were copied into `Assets/Game/Art/Sources/`. No Python image tool, image-to-mesh service, or other 3D generator was used.

The complete prompts are stored in [IMAGE_PROMPTS.md](IMAGE_PROMPTS.md). Important design choices were a single complete centered object, thick connected shapes, no floor/contact shadow, no external glow, and soft studio shading. These reduce ambiguity for single-image generation.

Source images are included so reproducing the model stage does not require regenerating the images. New AI image calls will not necessarily reproduce the same PNG pixels.

## Step 2: run Idol Studio

### Manual GUI workflow

1. Use an already-built [Idol Studio](https://github.com/shohdi/idol-csharp) installation.
2. Clear **Real photograph** because these are rendered/generated source images; this selects synthetic framing.
3. Set **Steps = 50** and the count/seed from the table below.
4. Browse to each PNG and allow conversion to complete.
5. Save the complete Gaussian PLY. Rename its extension to `.idolply` and place it in the game's `Assets/Game/Art/Splats/` folder. This changes the extension only, not its contents.

| Name | Input | Output | Gaussians | Seed |
| --- | --- | --- | ---: | ---: |
| Courier | `courier.png` | `courier.idolply` | 65,536 | 1042 |
| Sun crystal | `sun-crystal.png` | `sun-crystal.idolply` | 32,768 | 2042 |
| Void rock | `void-rock.png` | `void-rock.idolply` | 32,768 | 3042 |

All use guidance 3 and time shift 3. The smaller prop budgets keep the running game practical while retaining the complete output of each generation.

### Recorded C# batch workflow

`Tools/AssetGenerator` calls `IdolPipeline.LoadAsync` and `GenerateAsync` from already-built Idol Studio assemblies. It verifies cached model files, requests no downloads, reads no Hugging Face token, and does not build or modify the existing repository. Model generation requires the compatible NVIDIA driver and locally cached Idol/encoder weights. Set up those models through Idol Studio separately if necessary.

```powershell
./Tools/GenerateAssets.ps1 -IdolStudioBuildDir 'C:\path\to\idol\src\Idol.Inference\bin\Release\net9.0-windows'
```

The generator skips existing output files to prevent accidental replacement. To intentionally regenerate an asset, back up/remove only its `.idolply` and run the corresponding name. A generated asset's provenance JSON includes its source hash, original output hash, model revision, tool commit and settings. File hashes establish which supplied files were used; identical seeds across different GPU backends are not a promise of bit-identical regeneration.

## Step 3: import and assemble

Unity's `IdolPlyImporter` imports each `.idolply` as a data asset and prefab. The editor setup creates a single bootstrap scene, assigns those three data assets and the Gaussian shader, and registers the scene for builds.

At runtime, `RelicDriftGame` builds the camera, actor pools, 2D UI and audio. All world actors contain `IdolGaussianRenderer`; no visible `MeshRenderer`, `MeshFilter`, or `SkinnedMeshRenderer` is used. The renderer shares immutable GPU buffers, keeps all splats, orders separated actors by camera depth, and caches per-asset depth sorting when the camera-relative direction is unchanged.

Uniform scale and a child transform center each imported asset for gameplay. No Gaussian data is reshaped to make the courier, crystal, or rock.

## Step 4: gameplay and audio

Three fixed lanes keep controls simple. Rows reserve an escape lane and put crystals on a safe route. Speed increases over the 60-second run. Scores reward consecutive pickups; three impacts end a run. Hovering/banking the courier and spinning the crystals provide animation without modeling or skeletal deformation.

`GameRules.cs` separates score, shields, timer, pause and end-state behavior from the renderer. The interface explains controls before launch and provides pause, result, restart, sound and lane buttons. Best score and mute preference stay on the local machine.

## Step 5: build and verify

```powershell
./Tools/Build.ps1
./Tools/Run-Checks.ps1
```

The build uses Unity's own `BuildPipeline.BuildPlayer`. The checks audit the source assets and actual runtime actors, test real spawned pickups/hazards plus score/state transitions, and capture the real Windows player. See [VALIDATION.md](VALIDATION.md) for the results actually recorded.

The Windows ZIP includes the player, its data folder and engine dependencies. It contains the generated splat data, not the model weights or the asset-generation runtime.
